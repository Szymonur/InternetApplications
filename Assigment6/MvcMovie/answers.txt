1. What are the responsibilities of each layer of the MVC architecture and how are they connected?
Model: Manages the data and business logic of the application.
View: Handles the user interface and displays data to the user.
Controller: Acts as an intermediary; it processes incoming browser requests, retrieves data using the Model, and selects a View to render.

2. What are the naming conventions for models, controllers, controller actions, views folders and views themselves?
Models: Typically singular nouns (e.g., Movie).
Controllers: Plural name of the model followed by "Controller" (e.g., MoviesController).
Actions: Names like Index, Details, Create, Edit, or Delete.
View folders: Named after the controller (e.g., Views/Movies).
Views: Match the name of the action they correspond to (e.g., Index.cshtml).

3. How to pass data from controllers to views (2 options)?
- Using ViewData or ViewBag (dynamic containers for small amounts of data).
- Using a strongly-typed Model (passing an object directly to the view via @model).

4. How to map URL’s to controller actions?
Mapping is handled by routing defined in Program.cs. The default route template is "{controller=Home}/{action=Index}/{id?}", 
which maps a URL like /Movies/Edit/5 to the Edit action of the Movies controller with an ID of 5.

5. How to restrict controller actions to be executed only via certain HTTP request types (e.g., only via POST)?
By using action attributes like [HttpGet], [HttpPost], [HttpPut], or [HttpDelete] above the action method.

6. How to make sure a controller action can only be called through a form on our website and not through some external request?
By using the [ValidateAntiForgeryToken] attribute on the POST action method and ensuring the form in the view includes 
a hidden anti-forgery token (automatically handled by ASP.NET Core Tag Helpers).

7. Where do you define data validation and how do you ensure it in views and controllers?
- Define: Using Data Annotations (like [Required], [StringLength], [Range]) in the Model class.
- Controllers: Check the ModelState.IsValid property before saving data.
- Views: Use validation tag helpers (asp-validation-for and asp-validation-summary) to display error messages to the user.
